# Verify and Fix - テスト確認と修正

## 目的
テストの実行結果を確認し、必要な修正を行う

## 手順

### 1. テスト実行と結果確認

#### 単体テスト実行
```bash
# 特定ファイルのテスト
fvm flutter test test/path/to/test_file_test.dart

# 全テスト実行
fvm flutter test

# カバレッジ付き実行
fvm flutter test --coverage
```

#### 実行結果
```
✅ 成功: [X]件
❌ 失敗: [Y]件
⏭️ スキップ: [Z]件
```

### 2. 失敗テストの分析

#### 失敗テスト一覧

|---------|-----------|------|--------|
| test_1  | [エラー]  | [原因] | 高/中/低 |
| test_2  | [エラー]  | [原因] | 高/中/低 |

#### エラーパターン分類
- [ ] アサーションエラー（期待値と実際の値の不一致）
- [ ] 例外・エラーの発生
- [ ] タイムアウト
- [ ] セットアップ/ティアダウンの問題
- [ ] モック/スタブの問題

### 3. 修正実施

#### 修正方針
1. **テストの問題** → テストコードを修正
2. **実装の問題** → 実装コードを修正
3. **仕様の問題** → 仕様を確認して両方修正

#### 修正作業
```dart

[問題のあるコード]

```

### 6. 最終確認チェックリスト

#### テスト品質
- [ ] 全テストが成功している
- [ ] カバレッジが80%以上
- [ ] エッジケースがテストされている
- [ ] モックが適切に使用されている

#### コード品質
- [ ] 静的解析でエラーがない
- [ ] コードがフォーマットされている
- [ ] 不要なコメント/デバッグコードがない
- [ ] エラーハンドリングが適切

#### パフォーマンス
- [ ] テストの実行時間が妥当（各テスト1秒以内）
- [ ] メモリリークがない
- [ ] 不要な処理がない

## トラブルシューティング

### よくある問題と解決策

1. **モックが正しく動作しない**
   - モックの設定を確認
   - `when().thenReturn()`の設定確認

2. **非同期テストが失敗する**
   - `async`/`await`の使用確認
   - `expectLater`の使用検討

3. **テストが不安定（flaky）**
   - タイミング依存の処理を確認
   - 固定値の使用を検討

4. **セットアップエラー**
   - `setUp()`/`tearDown()`の確認
   - 初期化順序の確認

## 修正の優先順位
1. **高**: ビルドを壊すエラー
2. **中**: 機能に影響するエラー
3. **低**: コードスタイル、最適化
