# TDD Implement - テスト駆動実装

## 目的
t-wadaの推奨するテスト駆動開発の手法で、タスクごとに実装を進める

## 手順

### 1. テストケース作成（ドキュメントベース）
**重要**: コードを見る前に、仕様・ドキュメントからテストケースを作成すること

#### 正常系テストケース
- [ ] ケース1: [説明]
- [ ] ケース2: [説明]

#### 異常系テストケース
- [ ] エラーケース1: [説明]
- [ ] エラーケース2: [説明]

#### エッジケース（必須）
- [ ] 境界値: [説明]
- [ ] NULL/空: [説明]
- [ ] 極端な値: [説明]

### 2. テストコード作成
```dart
// テストコードをここに記述
// 網羅的にテストを書く
```

### 3. RED - テストが失敗することを確認
```bash
# テスト実行コマンド
fvm flutter test test/path/to/test_file_test.dart

# 結果：
# [ ] 全てのテストが失敗することを確認
```

### 4. GREEN - 最小限の実装
```dart
// 実装コードをここに記述
// テストを通すための最小限の実装
```

### 5. テストが通ることを確認
```bash
# テスト実行コマンド
fvm flutter test test/path/to/test_file_test.dart

# 結果：
# [ ] 全てのテストが成功することを確認
```

### 6. REFACTOR - リファクタリング（必要に応じて）
- [ ] コードの重複を削除
- [ ] 可読性の向上
- [ ] パフォーマンス改善

### 7. 最終確認
- [ ] 全テストが通る
- [ ] カバレッジが十分
- [ ] エッジケースが網羅されている

---

## 実行時の注意
1. **絶対にコードから先に書かない**
2. **テストケースは仕様書・要件から作成**
3. **エッジケースを必ず含める**
4. **REDフェーズをスキップしない**

## チェックリスト
- [ ] ドキュメントからテストケースを作成した
- [ ] エッジケースを含めた
- [ ] テストが失敗することを確認した（RED）
- [ ] 最小限の実装でテストを通した（GREEN）
- [ ] 必要に応じてリファクタリングした（REFACTOR）
